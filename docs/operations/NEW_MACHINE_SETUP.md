# ModelPath beta6 公司部署指南

## 直接启动

1. 保留公司现有 Node.js **22.18.0**，命令行 `node --version` 应显示 `v22.18.0`。
2. 将 beta6 压缩包完整解压到一个新目录，例如 `D:\ModelPath-beta6`。
3. 停止占用 **8765** 端口的旧版网站，双击新目录中的 **start-lan.bat**。
4. 启动脚本会检查依赖；首次安装需要 npm 软件源或公司内部镜像。
5. 同事访问 **http://100.100.40.76:8765/**。页面顶部应显示 **V1.0 BETA6**，词条库应包含 **27 个教学包**。
6. 保持启动终端开启。内容管理口令显示在终端中。

`100.100.40.76` 是公司广播主机的内网地址。脚本监听 `0.0.0.0:8765`，即接收该主机各网卡上的请求；不会修改主机网卡地址。访问失败时，检查主机是否仍使用该 IP，以及既有防火墙是否允许 8765 入站。

## 确认新版内容

在正式网站的共享词条库中搜索“全连接层”或“多层感知机（MLP）”，应当能直接打开。神经网络、激活函数、损失函数和反向传播也已采用新 PC 重做的版本。

访问 `http://100.100.40.76:8765/api/content/status`，应看到：
- `version: 1.0.0-beta.6`
- `questionCount: 34`
- `termCount: 27`
- `publicUrl: http://100.100.40.76:8765/`

如果仍然显示 beta4 或 beta5，先核对启动的是新目录里的脚本，以及旧服务是否仍占用端口，再刷新浏览器。

## 本机与独立实验室

- 仅本机使用：`start-local.bat`，http://127.0.0.1:8765/。
- 正式站 macOS/Linux 使用 `./start-lan.sh`、`./start-local.sh`。
- 内容实验室是独立交付包，在任意 PC 解压后运行其中的 `start-lab.bat` 或 `bash start-lab.sh`，访问 http://127.0.0.1:8766/。

实验室只使用它自己目录下的 `content-libraries/`，不依赖正式站源码或服务。作者导出 ZIP 后自行打开公司正式站内容管理，输入管理员提供的口令上传。旧 `.modelpath-lab/` 草稿先保留备份，按需迁移，不再由正式站启动同步。

## 升级与新增内容

广播主机将导入内容保存到正式站的 `content-libraries/`，作者草稿保存在各自独立实验室的 `content-libraries/`，各自定期备份。正式站不能只迁移 `dist/`。

如果旧站在你发送源码之后还有新题或新词条，按 ID 将这些增量合并到 beta6。不要把旧版本整库覆盖到新包，否则六个新版词条可能被还原。

后续更换公司广播主机 IP 时，可修改 `start-lan.bat`（或 `.sh`）中的 `--public-host` 参数；默认值为本次指定的 `100.100.40.76`。端口仍为 8765。

## 新增共享服务与升级数据

首次启动自动创建 `service-data/modelpath.sqlite`。正式服务应解压到公司主机本地磁盘，不在多机同时同步的 iCloud 数据库上运行。

如果已有 beta6 用户数据，先停止旧服务，再把整个 `service-data/` 迁移到新版本；同时保留 `content-libraries/` 和公司定制的 `agent-runtime/`。不要用随包的空数据目录覆盖旧数据。`MODELPATH_DATA_DIR` 可把数据存放在独立固定路径。

右上角先设置讨论显示名；进入题目或词条，选中文字后右键批注。其他同事能看到并回复。大模型默认没有接 API，配置方式见 `public/docs/COLLABORATION_AND_AGENT.md`。
