# 启动与依赖检查修订 · 2026-09-07

正式平台和独立实验室都继续支持公司 Node.js 22.18.0，依赖版本和内容包格式没有更换。

## 与旧版的不同

beta1／2 用 Python 提供静态网页；beta3／4 只检查 `node_modules/fflate` 目录，然后调用 `npm install`，并不完整检查安装退出码。beta5 起改用锁文件 `npm ci`，遇到非零退出码就终止。

此前确实存在检查标准不一致：首次安装失败后退出，第二次启动却可能因为依赖目录和元数据已经存在而跳过安装。这不证明依赖已完整、可用。用户报告的公司首次 npm 失败原因尚无完整日志，不能推断为某个确定的网络或 Windows 错误。

## 本次修订

- 每次启动都验证实际依赖版本和运行能力；不仅检查文件夹存在。
- 检查构建所需本机原生模块、TypeScript、tsx 和 Vitest，避免文件已解压但工具不能运行。
- 安装显式包含开发工具和当前系统的可选原生依赖，仍严格使用锁文件。
- npm 报错后先检查实际可用性；依赖版本正确且所有关键工具可运行时，保存警告并直接继续启动，不要求再双击，不重复安装。
- 仍有依赖不可用且遇到明确的网络、文件占用或缓存校验错误，自动等待并重试一次；不无限重试。未知错误且工具不可用时停止并保留报错。
- BAT 统一 UTF-8 提示、CRLF 换行和失败出口；`pushd` 支持带空格、中文及 Windows 网络路径。建议仍解压到本机磁盘运行。

运行检查通过后，同一次双击会继续启动网站，不需要手动再点一次。

## 仍然失败时

不要只重复双击。请提供窗口里最早的 npm 错误，或发送对应网站目录下的：

- `.modelpath-runtime/startup-last.log`：最近一次依赖检查。
- `.modelpath-runtime/startup-failed.log`：最近失败；后续成功不会覆盖它。
- `.modelpath-runtime/startup-warning.log`：npm 报错但实际工具可用、允许继续启动时保留的警告。

日志用于确认镜像、网络、权限、文件占用或工具执行错误。分享前仍请检查是否含公司内部信息；不要发送管理口令或 API Key。

验证边界：已在 Node 22.18.0 本地完成首次安装／第二次启动和自动化失败分支测试；尚无公司 Windows 实机报错可供复现，不能保证所有现场安装问题都已消除。
