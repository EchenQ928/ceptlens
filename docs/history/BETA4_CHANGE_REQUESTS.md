# ModelPath V1.0 beta4 变更基线

记录日期：2026-09-01  
当前状态：已实施并纳入 beta4；具体结果见 `RELEASE_NOTES_BETA4.md` 与 `SOURCE_REVIEW.md`。

## 1. 清除限制扩展性的冗余代码

### 问题根源

beta3 把“首版交付时恰好有 37 道 P0 题”误写成了运行时内容不变量：`validate-content.ts` 强制 `P0 === 37`。这只适合作为某次交付数据的验收记录，不应进入日常增删改的发布门禁。它导致网站虽然提供删除接口，管理员却无法真正删除任何现有题目。

### beta4 修改原则

- 删除题目总数、P0 数量、词条数量等与某次内容快照绑定的硬编码限制。
- 页面上的题目数、P0 数、教学包数和待补数全部从当前内容库动态计算。
- 内容校验只保留真实结构约束：Schema、唯一 ID、唯一顺序、答案与选项一致、显式链接与依赖声明一致、题目前置引用有效、教学包完整、源码依赖安全以及网站可构建。
- 删除题目时先报告受影响的前置关系；修复断链后允许发布，不再因为题库数量变化而失败。
- “37 道 V1 P0”只能存在于 beta3 发布说明或快照测试中，不得成为 beta4 运行逻辑。
- 全面搜索并处理同类问题：固定数量、固定内容 ID、只为旧 Demo 服务的分支、迁移期脚本、重复内容源、失效组件、无用 CSS/依赖、过时说明和无法触达的代码。
- 保留必要的产品约束，例如题型 Schema、管理口令、教学包安全检查和依赖完整性；清理的对象是与功能无关的限制，不是削弱数据安全。

### 验收

1. 管理员能新增、更新和删除任意合法题目，题库数量可以自然变化。
2. 删除后题库首页、筛选数量、学习顺序、考核准备页和内容管理页同步更新。
3. 删除导致前置断链时给出明确来源；修复后可发布并自动构建。
4. 源码中不存在 `P0 === 37`、`questions.length === 37` 等内容快照式运行限制。
5. 冗余清理不能改变题目包、教学包两个可迁移内容库的独立边界。
