# KV Cache 剩余题目设计草案

> 本文件是第 6～35 题的初稿。CeptCheck 暂不设置；答案用于学习模式，评分 rubric 后续隐藏在题目数据中。

## 6. Projection 与 Attention Computation 的区别

- **题型**：单选题
- **题干**：关于矩阵投影与注意力点积，下列说法最准确的是？
- **正确方向**：投影使用模型参数把隐藏状态变成 Q/K/V；注意力点积使用 Q 与 K 计算相关性，再用权重聚合 V。
- **干扰项设计**：把投影权重当成运行时缓存；把 QK 点积说成生成 K/V 的过程；把 Value 说成决定注意力分数的张量。
- **学习解答**：投影是参数化的线性变换，负责产生 Q、K、V；注意力计算接收这些张量，先用 Q 与 K 得到分数，再用分数加权 V。两者的输入、输出和参数角色不同。

## 7. Cross-Attention 与 Decoder Self-Attention 的缓存差异

- **题型**：简答题
- **题干**：比较 Encoder-Decoder 架构中 Cross-Attention 的 KV Cache 与 Decoder-Only Self-Attention 的 KV Cache。
- **核心解答**：Decoder-Only 的 K/V 来自不断增长的目标序列，每生成一个 Token 就追加新的 K/V。Cross-Attention 的 K/V 来自已经编码完成的源序列，源序列固定后通常只需计算并缓存一次；Decoder 侧的 Query 仍随生成步骤变化。
- **评分依据**：来源、生命周期、追加行为、Query 变化四点。

## 8. 两类 KV Cache 的生命周期

- **题型**：简答题
- **题干**：在 Encoder-Decoder 结构中，Self-Attention KV Cache 与 Cross-Attention KV Cache 的生命周期有何不同？
- **核心解答**：Encoder Self-Attention 的中间结果通常在编码阶段使用，完成编码后即可释放或交给后续模块；Decoder Self-Attention 的缓存随目标序列增长，直到生成结束；Cross-Attention 的 K/V 在源序列编码完成后建立，并可供整个 Decode 过程重复读取。
- **设计重点**：区分“源序列固定”与“目标序列增长”。

## 9. Causal Mask 在 Prefill 与 Decode 中的差异

- **题型**：单选题
- **题干**：为什么 Prefill 通常需要处理完整的因果掩码，而 Decode 通常只需限制当前 Query 访问未来位置？
- **正确方向**：Prefill 同时计算多个位置，必须屏蔽每个位置右侧的未来 Token；Decode 的当前 Query 位于序列末端，历史缓存和当前 K/V 都可访问，天然没有更晚的位置。
- **干扰项设计**：说 Decode 完全没有因果约束；说 KV Cache 自动改变了注意力方向；说掩码只用于训练不用于推理。
- **学习解答**：Prefill 并行计算多个位置，需要用掩码保持因果性。Decode 每步只处理序列末端的新位置，它访问的是已有历史和当前位置，通常可以用长度或索引约束代替显式下三角矩阵。

## 10. 自回归生成为什么不能完全并行

- **题型**：简答题
- **题干**：为什么自回归生成无法像 Prefill 一样对所有待生成 Token 完全并行？
- **核心解答**：第 (t+1) 个 Token 的输入依赖第 (t) 个 Token 的生成结果，而第 (t) 个结果又依赖更早结果。这个跨步依赖形成串行链；Prefill 的输入全部已知，所以可以并行处理多个位置。
- **CeptCheck 暂不设置**。

## 11. 写入 Cache 的特征位于 Norm 前还是 Norm 后

- **题型**：简答题
- **题干**：在含残差连接和 LayerNorm/RMSNorm 的 Transformer Block 中，写入 KV Cache 的特征位于 Norm 之前还是之后？请说明判断依据。
- **核心解答**：K/V 应由该层注意力模块实际接收的隐藏状态计算，因此写入的是对应投影之前、经过该层规定的 Norm/残差路径处理后的输入表示。具体位置取决于 Pre-Norm 或 Post-Norm 的 Block 拓扑，不能脱离架构直接用“Norm 前”或“Norm 后”概括。
- **设计重点**：避免把实现差异简化成固定答案。

## 13. 无 Cache 与有 Cache 的累积复杂度

- **题型**：简答题
- **题干**：生成 (N) 个 Token 时，不使用 KV Cache 与使用 KV Cache 的主要累积计算复杂度分别如何变化？
- **核心解答**：无 Cache 时，第 (t) 步会重新处理长度约为 (t) 的历史，累积量呈二次增长，典型项为 (O(N^2d))。有 Cache 时，历史 K/V 投影不再重复，投影部分按每步新增 Token 计算；当前 Query 仍需访问长度增长的历史 K/V，因此注意力读取和点积仍随上下文增长。
- **设计重点**：明确 Cache 降低重复投影，不把所有 Decode 计算都说成常数。

## 14. 二次复杂度的等差数列推导

- **题型**：主观题
- **题干**：请推导无 KV Cache 时生成 (N) 个 Token 的累积计算量为什么出现二次增长。
- **参考解答**：第 (t) 步需要处理约 (t) 个历史位置，若单个位置的相关计算量为 (O(d))，总量为
  \\[O(d)+O(2d)+\cdots+O(Nd)=O\left(d\frac{N(N+1)}2\right)=O(N^2d)。\\]
  二次项来自每一步长度不同的计算量跨步骤累加。

## 15. 为什么说投影开销降为单步 (O(1)

- **题型**：单选题
- **题干**：引入 KV Cache 后，Decode 单步投影开销常被描述为 (O(1))。这里的含义是什么？
- **正确方向**：相对于历史序列长度，当前步的 Q/K/V 投影只处理一个新增 Token；模型维度和权重规模视为固定。
- **干扰项设计**：声称整个 Decode 单步总复杂度为常数；声称注意力不再读取历史；声称 KV Cache 让模型参数变少。
- **学习解答**：(O(1)) 只针对“新增 Token 的线性投影”相对于序列长度的增长而言。当前 Query 仍需与历史 K 做注意力，并读取历史 V，所以整个单步并非所有部分都为常数。

## 16. 带 KV Cache 的单步注意力递推

- **题型**：主观题
- **题干**：请写出带 KV Cache 的单步 Self-Attention 递推过程。
- **参考解答**：对当前隐藏状态 (x_t) 计算 (q_t=x_tW_Q,k_t=x_tW_K,v_t=x_tW_V)；将 (k_t,v_t) 追加到 (K_{1:t},V_{1:t})；计算 (s_t=q_tK_{1:t}^T/\sqrt{d_k})；得到 (a_t=softmax(s_t))；输出 (o_t=a_tV_{1:t})，再经过输出投影和后续 Block。

## 17. MHA 单步 Decode 的 FLOPs

- **题型**：主观题
- **题干**：请按 Q/K/V 投影、Attention Score、Softmax、加权 Value 和输出投影几个部分，建立标准 MHA 单步 Decode 的 FLOPs 表达式。
- **核心解答**：设模型维度为 (d)、历史长度为 (S)、头数为 (H)、单头维度为 (d_h)，需分别统计三个投影、每头 (q_tK^T)、Softmax、每头权重乘 V 和 (W_O) 投影。主导项通常来自投影的 (O(d^2)) 与注意力读写的 (O(Sd))；Softmax 的精确常数取决于实现。
- **设计重点**：要求列项，避免只写一个未经假设说明的总数。

## 18. 单请求单层单 Token 的 KV Cache 显存公式

- **题型**：计算题
- **题干**：推导单请求、单层、单 Token 的 KV Cache 显存占用，参数为头数 (H)、单头维度 (d_h)、每元素字节数 (P)。
- **参考解答**：Key 有 (Hd_h) 个元素，Value 也有 (Hd_h) 个元素；合计 (2Hd_h) 个元素，因此占用 (2Hd_hP) Byte。若扩展到 (L) 层、序列长度 (S)、Batch Size (B)，总量为 (2BLSHd_hP)。

## 19. 70B 模型 KV Cache 显存计算

- **题型**：计算题
- **题干**：80 层、KV 维度 8192、FP16、Batch Size=16、上下文长度=8192 时，仅 KV Cache 需要多少显存？
- **参考解答**：每个 Token、每层的 K/V 合计 (2\times8192\times2) Byte；总量为 (2\times16\times8192\times80\times8192\times2) Byte，约为 32 GiB（按十进制 GB 表示约 34.36 GB）。答案需注明 GiB/GB 口径。

## 20. MHA 拆成多个头是否放大投影 FLOPs

- **题型**：单选题
- **题干**：在隐藏维度 (d) 固定时，将注意力拆成 (H) 个头后，线性投影 FLOPs 如何变化？
- **正确方向**：若各头维度总和仍为 (d)，拼接后的 Q/K/V 投影矩阵总维度不变，线性投影主项不因拆头而放大 (H) 倍。
- **干扰项设计**：把“头数增加”直接等同于“矩阵乘法次数增加”；把单头维度也固定为 (d)；把注意力点积开销与投影开销混为一谈。
- **学习解答**：多头改变表示的分组方式。只要 (Hd_h=d)，Q/K/V 的总投影维度不变；头内注意力的组织方式会改变，但不能据此断言线性投影放大 (H) 倍。

## 21. Single-Head 与 MHA 投影量相等

- **题型**：主观题
- **题干**：证明相同隐藏维度 (d) 下，Single-Head 与 MHA 的线性投影 FLOPs 严格相等。
- **参考解答**：Single-Head 的 Q 投影为 (d\times d)。MHA 将输出拆成 (H) 个 (d_h) 维头，且 (Hd_h=d)，合并后的 Q 投影仍为 (d\times(Hd_h)=d\times d)。K、V 同理，三组投影的矩阵乘法维度总量相同。

## 22. Roofline：Prefill 与 Decode 的瓶颈

- **题型**：简答题
- **题干**：从 Roofline Model 解释为什么 Prefill 通常偏 Compute-bound，而 Decode 通常偏 Memory-bound。
- **核心解答**：Prefill 以较大矩阵批量处理多个 Token，算术强度高，计算单元利用率更容易提升。Decode 每步新增 Token 少，却要读取大模型权重和历史 KV，算术强度较低，显存带宽更容易成为限制。两者是典型倾向，实际边界随 Batch、序列长度和硬件变化。

## 23. 算术强度随 Batch Size 与序列长度变化

- **题型**：主观题
- **题干**：分析 Decode 阶段算术强度如何随 Batch Size 和序列长度变化。
- **参考解答**：Batch 增大时，同一份权重读取可服务更多请求，计算量相对数据搬运量增加，算术强度通常上升。序列长度增加会增加每步对历史 KV 的读取；在其他条件固定时，KV 搬运增长会压低算术强度。具体趋势取决于权重读取、KV 读取和实现中的融合方式。

## 24. Roofline 数值题

- **题型**：计算题
- **题干**：显存带宽 1.5 TB/s、算力 300 TFLOPS，Batch Size=1、序列长度 2048 的 Decode 单步算术强度为 (X) FLOPs/Byte。请根据 Roofline 判断 MFU 上限。
- **设计要求**：题包中必须先明确模型维度、层数、KV 维度和是否计入权重读取；否则数值不唯一。
- **参考解答框架**：先计算单步 FLOPs 与总读写字节数，得到 (I=F/B)；带宽 Roof 为 (1.5\times10^{12}I) FLOP/s；与 300 TFLOPS 取较小值，再除以 300 TFLOPS 得到理论 MFU 上限。

## 25. Batch Size 对权重与 KV 读取比例的影响

- **题型**：主观题
- **题干**：设模型参数量为 (P)，全量 KV Cache 占用为 (M_{kv})。Decode 单步中，权重读取与 KV Cache 读取的带宽消耗比例如何随 Batch Size 变化？
- **核心解答**：若权重可在批次内共同使用，权重读取量近似按一次加载计，而每个请求仍需读取自己的历史 KV。Batch 增大后，权重读取摊到更多请求上，KV 读取在总带宽中的占比通常上升；精确比例还取决于序列长度、KV 维度、缓存命中和调度方式。

## 26. KV Cache 低精度对 Decode 时延的影响

- **题型**：主观题
- **题干**：将 KV Cache 从 FP16 降为 FP8 或 INT4，在算力不变时，Decode 时延理论上如何变化？实际收益受哪些因素限制？
- **参考解答**：缓存字节数理论上按每元素字节数下降，带宽受限部分的上限可接近 2 倍或 4 倍；整体时延还包含投影、量化/反量化、Kernel 效率、访存对齐、带宽利用率和精度损失，因此端到端收益通常低于理想比例。

## 27. MQA 的核心设计

- **题型**：单选题
- **题干**：MQA 相对标准 MHA 的核心变化是什么？
- **正确方向**：多个 Query 头共享较少数量的 Key/Value 头，常见极端是所有 Query 头共享一组 K/V。
- **干扰项设计**：把 MQA 说成减少 Query 头；把共享模型权重说成共享运行时 KV；把 MQA 说成取消注意力头。
- **学习解答**：MQA 保留多组 Query 表达能力，让多组 Query 共享 K/V 头，从而减少 KV Cache 的宽度和 Decode 时的 KV 读取量。

## 28. GQA 的折中

- **题型**：计算与解释题
- **题干**：GQA 如何在 MHA 与 MQA 之间折中？当 Query 头数为 (H)、KV 头数为 (G) 时，KV Cache 与 MHA 的占用比是多少？
- **参考解答**：GQA 将 Query 头分成若干组，每组共享一个 K/V 头。KV Cache 占用与 KV 头数 (G) 成正比；相对 MHA 的比值为 (G/H)。MHA 对应 (G=H)，MQA 对应 (G=1)。

## 29. 动态 KV Cache 的显存碎片

- **题型**：主观题
- **题干**：动态增长的 KV Cache 在传统 Tensor 显存管理中会产生哪些内碎片和外碎片问题？
- **核心解答**：请求长度不同、增长速度不同会导致预留块大小与实际使用量不匹配，形成内碎片；频繁申请、扩展和释放会把空闲空间分散，形成外碎片。即使总空闲显存足够，也可能找不到连续的大块空间，降低并发能力并增加搬迁开销。

## 30. PagedAttention

- **题型**：主观题
- **题干**：详述 PagedAttention 如何借鉴虚拟内存分页机制管理 KV Cache。
- **参考解答**：系统把逻辑上的连续 KV 序列切成固定大小的块，物理显存中按需分配不连续页面，再用块表把逻辑位置映射到物理块。请求增长时只需申请新块，释放时回收整块，减少连续扩展和碎片；相同前缀还可以通过块引用共享。

## 31. Prefill/Decode 解耦

- **题型**：主观题
- **题干**：什么是 Disaggregated Prefill/Decode？为什么拆分物理节点？KV Cache 如何在两个阶段之间传输？
- **参考解答**：Prefill 节点负责高并行上下文计算，Decode 节点负责逐 Token 生成。拆分可以让两类负载分别按算力、带宽和队列特征调度，减少互相干扰。Prefill 完成后将 K/V 通过高速网络或专用传输路径发送给 Decode 节点，Decode 再将其接入本地缓存。

## 32. TTFT、TPOT/ITL 与 Throughput

- **题型**：匹配与解释题
- **题干**：说明 KV Cache 管理效率如何影响 TTFT、TPOT/ITL 和 Throughput。
- **参考解答**：Prefill 的排队和计算影响 TTFT；Decode 中 KV 读取与调度影响 TPOT/ITL；有效的缓存复用、分页和批调度可以提高并发请求处理量，从而提升 Throughput。三者受共享 GPU 资源影响，需要结合负载观察，不能用单一指标代表整体性能。

## 33. KV Cache OOM 的主动防御

- **题型**：多选题
- **题干**：推理服务因并发升高而接近 KV Cache OOM 时，哪些策略属于常见的主动防御或降级调度？
- **正确方向**：限制最大上下文或输出长度、拒绝或排队新请求、抢占低优先级请求、将部分状态卸载、重新计算被驱逐的 KV、降低 KV 精度。
- **干扰项设计**：把删除模型权重说成只影响当前请求；把无限增加 Batch 说成必然缓解 OOM；把清空所有 KV Cache 说成无损操作。
- **学习解答**：服务通常通过 admission control、排队、抢占、重计算、卸载、量化和优先级调度控制峰值。每种策略都会在时延、吞吐、精度或重复计算之间产生取舍。

## 34. K Cache 与 V Cache 的量化差异

- **题型**：主观题
- **题干**：比较 Key Cache 与 Value Cache 的数值分布特征，并说明低比特量化时常见的粒度选择。
- **参考解答**：Key 会参与 Query-Key 点积，异常值可能直接影响注意力分数；Value 会进入加权聚合，误差会传播到输出，两者的敏感位置不同。实际方案会根据模型和校准结果选择 Per-token、Per-channel 或 Group-wise 粒度，并可能对 K/V 使用不同的缩放和保护策略。不能脱离模型分布假设固定一种粒度。

## 35. 短序列模型使用 KV Cache 的首要目的

- **题型**：单选题
- **题干**：在输入序列较短的 Cross-Attention 信号模型中，使用 KV Cache 的首要目的更可能是什么？
- **正确方向**：减少重复的投影或跨步计算，降低时延并保持稳定的在线推理流程；显存节省可能不是主要收益。
- **干扰项设计**：把所有使用 KV Cache 都归因于省显存；把短序列说成无法使用 Cache；把 Cache 说成提升模型表达能力或改变预测目标。
- **学习解答**：当序列很短时，缓存节省的显存有限，但避免重复计算、减少在线延迟和简化连续推理流程仍然有价值。缓存的主要收益应根据重复计算量、访问成本和系统目标判断。
