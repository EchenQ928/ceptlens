# AI 模型学习词条设计

把词条当作一位优秀工程师根据同事已有知识展开的单概念教学，而不是组件陈列。每个词条必须单独设计；不要套用机械模板或为了“丰富”而加入控件。

## 工作顺序

1. 明确核心结论、读者已掌握的知识和当前新增的知识。先根据学习路径或用户约定明确读者已掌握的前置知识。独立可读指页面不依赖特定入口，不等于每页都从零教学；已掌握的基础概念只需自然提及和链接，把篇幅留给当前概念新增的结构与机制。未纳入前置知识、又会阻碍主线理解的概念，才在当前页补最低解释。缺包登记为后续任务，不越过当前授权范围生成。
2. 写首屏正文：用自然语言交代它属于什么、核心特点是什么。已知概念和名称缩写可以直接承接；不重复前置课程的通用输入—输出解释。若有必要的结构图，默认状态应无需操作即可读懂。
3. 在首次需要处自然链接前置概念，只对读者尚未掌握且影响主线的概念补最低解释；不要另设“相关词条”清单代替正文链接。
4. 判断是否真的需要可视化或交互。只有当它能回答一个清楚的因果问题，且状态变化明显可解释时才保留。
5. 再补公式、代码和工程边界。公式中的每个符号必须就近解释；代码要映射回正文与图中的对象。
6. 用 `references/design-and-review-standard.md` 做设计审查与交付审查。未通过停止条件时，简化或重构，不要继续堆内容。

## 强制原则

- 解释先于操作。操作提示只能说明“怎么用”，不能代替“这是什么、为什么”。
- 结构先于数字。先让读者认出输入、核心处理、输出和方向，再给数值演算；禁止用一串数字迫使读者反推网络结构。
- 静态理解先于动态探索。默认状态必须已经呈现核心结论；交互只用于观察一个必要变化，不能承担“把概念拼出来”的任务。
- 交互有认知成本。若读者需要超过一句话学习控件，或必须先试错才知道颜色、字母、节点和状态代表什么，删除交互或拆成更小的静态步骤。
- 图要能脱离正文独立阅读。遮住图外文字后，读者仍应能指出输入、处理、输出、方向和当前结论；所有符号在第一次出现处就近落到具体对象上。
- 首屏只走一条主线。前置、变体、优化、公式、代码和硬件边界采用渐进披露；不得把“内容齐全”误当作“容易理解”。
- 本体先于区分。页面先完整讲清概念是什么、为什么需要、怎样工作；禁止凭空假设读者持有某种错误观点，再围绕“它不是什么”“为什么不等于某物”组织正文。只有题目、用户反馈或实际审查已经证明某个混淆存在，而且该区分会影响正确使用时，才在本体讲清后补充。
- 前置缺口不靠防御性文字填补。正文依赖尚未解释的主干概念时，当前页给一句最低定义并自然链接独立词条；不能跳过前置词条，直接讨论高级变体与另一个概念的差别。
- 新对象第一次出现即解释。已约定的前置知识可以承接；本页新引入的术语、符号、图例和控件仍需就近说明。
- 一个交互只回答一个核心问题。若不能用一句话说出它验证什么，删除或拆分。
- 比较轴必须显式。若比较模型复杂度、正则强度或训练阶段，必须在图和正文中直接写出来。
- 结果必须直接标注。解释页不要再让用户诊断一个页面已经应该说明的现象。
- 图必须保留概念结构。讲全连接层 Dropout 就画全连接网络；讲逐通道卷积就画通道、卷积核和输出的对应关系。
- 视觉状态必须有语义。装饰性“快照”、没有可见差异的采样或不影响结论的控件一律删除。
- 数学使用语义化上下标/上标或可靠数学渲染，禁止把源码式裸下划线当公式排版。
- 公式是对已理解过程的压缩。先认出对象和关系，可用熟悉的简单算术说明局部机制；抽象公式放在这之后，并按同一图中对象逐项解释符号。不要把“先解释符号”误用为“先教符号才能看例子”。
- 区分查看与修改。选择一个对象只切换它的讲解，不改变计算；改变一个输入时，相关图、演算与结果同步更新。对比必须注明基准；固定示例必须明确不随交互更新。
- 概念深度来自因果、边界和迁移，不来自模块数量。表达的先后层次与删冗原则见设计审查规范。

## 领域红线

- 过拟合：明确区分训练集与验证集；直接说明“最后一个 epoch 的权重不一定是验证集上最好的权重”。比较欠拟合、合理拟合、过拟合时，公开模型复杂度这一比较轴。
- 正则化：先解释正则化目的，再定义强度因子 λ，之后才出现控制器。固定 λ 时最小化对应目标；改变 λ 会改变目标函数，不能横向比较不同 λ 的总训练目标来选择 λ。用验证集选择 λ。
- Dropout：先展示它发生在哪一层、哪些神经元及连接被屏蔽，再解释训练时随机性和缩放。缩放至少用一个可手算的单神经元期望例子说明。
- RNN与BPTT：必须先讲清一个时间步：当前输入x_t与上一隐藏状态h_{t-1}怎样进入同一个Cell，如何得到新隐藏状态h_t，以及h_t如何继续传给下一步并可经输出层得到y_t。之后才展开T步并解释参数共享。BPTT中的“时间”必须解释为序列位置轴；先解释“展开同一个Cell的多次调用”，再讲前向保存、反向读取、链式法则和共享参数梯度累加。

## 输出要求

设计稿应给出：核心结论、真实前置依赖与读者起点、承接已有知识的正文、页面阅读顺序、最小静态结构图、是否确有必要的唯一核心交互及其状态/反馈、公式与符号说明、正文内链接词条、工程边界、应删除的内容、验收方式。若是审查任务，先指出因果链在哪一处断裂，再给最小重构方案；若原结构本身增加学习成本，可以推翻重构，不以保留既有组件为目标。
