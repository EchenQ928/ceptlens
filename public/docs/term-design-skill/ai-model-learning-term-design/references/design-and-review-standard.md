# AI 模型学习词条设计与审查规范

## 1. 读者与目标

默认读者具备软件开发经验；模型知识起点以学习路径和用户约定为准。先根据学习路径或用户约定明确读者已掌握的前置知识。独立可读指页面不依赖特定入口，不等于每页都从零教学；已掌握的基础概念只需自然提及和链接，把篇幅留给当前概念新增的结构与机制。未纳入前置知识、又会阻碍主线理解的概念，才在当前页补最低解释。

一个合格词条让读者不靠记口号，能够回答：

1. 它是什么，解决什么问题？
2. 输入经过什么机制得到输出？
3. 改变哪个因素会导致什么现象，为什么？
4. 什么时候适合用，什么时候会失败或不值得用？
5. 能否用自己的话说明一个新例子中的同类机制？词条独立成立，不要求读者来自某道题。

回答这些问题时，以概念本体为主线。不要为了显得严谨，主动发明一个“有人可能会认为……”的观点再反驳。

机制之间的递进要完整：先交代已有机制的能力，再以具体局限引出新机制，最后回到两者如何配合；不能把新机制直接宣布为“关键”而省略这条推理。章节标题采用自然中文。

先说清具体对象做了什么、为什么有用，再命名抽象概念，最后说明必要边界。不要把机制、术语定义和限定条件挤在同一段；也不要只用“加工、组合、表示”等抽象词反复转述而没有增加信息。精简时删去已知铺垫与重复结论，保留因果关系和必要对应。

## 2. 推荐阅读层次

层次是信息顺序，不是固定 UI 模板。

### 第一层：不操作即可理解

- 一句通俗定义，避免用同义术语循环解释。
- 一个具体情境或最小数字例子。
- 一条完整因果链，例如“模型容量过大 → 能记住训练样本中的噪声 → 训练误差继续下降而验证误差上升”。
- 本词条理解所必需的适用范围或工程边界。没有真实混淆证据时，不额外设置“误区反驳”。

第一层还必须满足“最小主线”约束：

- 先出现输入、核心处理、输出和方向，再出现数值、公式细节和工程分支；
- 首个图只承载一条因果链，不能同时教授结构、训练、复杂度、硬件映射和故障诊断；
- 图外说明被遮住后，读者仍能从图中读出对象名称、连接方向和结论；
- 若读者需要先学习图的阅读规则，图应继续简化或拆成连续静态步骤。

### 第二层：针对概念的可视化或交互

交互设计前先写一句：`读者操作 X，是为了看见 Y，从而理解 Z。`

若这句话写不清，不做交互。若静态图已经足够，不强行交互。

交互要支付“交互税”。保留前必须同时回答：

1. 默认静态状态是否已经讲清概念？
2. 操作是否只改变一个已定义变量？
3. 按钮文字是否直接说明会改变什么？
4. 操作后能否在原位置立即看到变化和结论？
5. 使用方法是否能用一句话说完？

任一答案为否，删除交互或拆分。动画若只是让元素依次出现，而没有揭示静态图看不到的因果关系，也应删除。

交互必须满足：

- 操作对象已在正文中定义；
- 初始状态无需猜测；
- 每次操作产生肉眼可辨的变化；
- 变化旁边直接解释原因；
- 不同时改变多个关键变量；
- 不把“猜对术语”当作理解机制。
- 页面视觉延续宿主平台的设计变量与控件语言。用标注、位置和字重保持教学重点，避免为不同知识角色添加一整套无必要的配色和图标。
- 区分执行运算的对象与产生的数值；在节点、连接、演算中保持一致的符号对应，并就近解释符号。核心角色的名称与对应数值要在演算中一起突出。
- 删除仅用于演示已经显然成立的变化的控制器。交互的价值取决于是否帮助理解当前机制，不能仅以“操作后数值会变”作为保留理由。

概念与视觉结构必须同构：

- 全连接层：显示层、神经元与全连接边；
- 卷积：显示输入局部区域、卷积核乘加与对应输出元素；
- 序列反向传播：显示时间展开和梯度链路；
- 量化：显示连续值、量化网格、舍入与误差；
- 正则化：显示相同数据与不同约束下模型形状、训练/验证表现的变化。

### 第三层：严谨表达与工程迁移

- 公式：每个符号就近定义，使用 `<sub>`、`<sup>`、MathML 或可靠数学渲染；禁止 `L_train` 之类裸下划线直接显示。
- 代码：只保留核心机制，并把变量对应到图中的对象。
- 复杂度：说明主要参数和算力来自哪里，必要时列时间/空间复杂度。
- 工程边界：说明训练与推理差异、硬件/NPU 约束、数值稳定性、算子支持和不适用场景。

公式必须沿“认出对象和关系 → 理解局部过程 → 抽象公式及符号映射”的顺序出现。局部过程可以先使用读者熟悉的简单算术，并在数字旁说明来源和作用；不要求先掌握一套字母才能看懂演算。抽象公式复用前面已经出现的对象，符号在公式旁逐项解释，不能另起一个例子让读者重新建立对应关系。

有交互时，明确区分两类操作：选择对象只切换观察位置，改变输入才重新计算。选择不能悄悄重置输入或其他中间状态；输入变化后，图、数值演算和解释须一致。变化摘要标明“初始值 → 当前值”，固定的公式例子则明确对应哪组输入。演示数据是手工构造还是实际训练所得，以及输出是什么量，都应就近交代。

## 3. 概念链接规则

- 链接直接嵌在题目、选项、答案解释和词条正文第一次出现的名词中。
- 链接前后句子本身要能读通；链接不是脚注符号。
- 已掌握的前置概念可直接使用并链接，新概念补最低解释；当前词条的核心机制不能外包给下一页。
- 若当前词条是某个基础概念的变体，基础概念必须先有独立入口。变体页不能以“与另一种做法的区别”代替对基础概念和变体机制的正向解释。
- 点击深入后保留浏览历史和返回路径，使读者能沿树枝探索再回到主干。
- 不以页面底部的“继续探索/相关词条”列表取代正文中的自然跳转。

## 4. 特殊主题的正确表达

### 过拟合

先定义训练集和验证集各自的角色。若用三组实验，必须直接写出模型复杂度逐步增加，并把结果标为：

- 简单模型：训练与验证都差，欠拟合；
- 合适模型：训练与验证都较好且差距合理；
- 过复杂模型：训练继续变好、验证先好后坏，过拟合。

清楚写出：最终 epoch 的权重不一定是验证集上表现最好的权重；检查点选择依据是验证指标，而不是“越晚越好”。不要用含义不明的决策边界快照，也不要在已经标注结果后再加诊断选择题。

### 正则化

顺序必须是：目的 → 无/适中/过强的直观现象 → λ 的含义 → L1/L2 的差异 → 目标函数 → 工程边界。

区分两件事：

- 固定 λ：训练算法最小化 `数据损失 + λ × 正则项`；
- 选择 λ：不同 λ 对应不同训练目标，不能用各自总目标数值直接横比，必须比较同一验证指标。

图中的点、拟合线、训练误差、验证误差和颜色在出现前定义。若 λ=0 的总目标天然更小，不得把它画成“最优正则强度”的证据。

### Dropout

若以全连接层为例，画出完整的输入层、隐藏层、输出层和连接。被屏蔽的隐藏神经元及其入边、出边一起弱化。先解释训练时随机屏蔽，再用例如 `h=2, p=0.5` 的两种结果说明 inverted Dropout：保留时输出 4，屏蔽时输出 0，期望仍为 2。不要添加没有明显变化或不能支持核心结论的“多次采样”图。

### RNN、T步与BPTT

RNN必须按以下顺序建立：

1. 只画一个位置t，明确x_t是当前输入、h_{t-1}是上一位置的历史摘要；
2. 显示两路输入在同一个Cell内被分别变换、相加、激活，得到h_t；
3. 显示h_t沿隐藏状态线传给下一位置，并可经任务输出层得到y_t；若框架把h_t序列称为output，应就近说明API语义；
4. 再把同一个Cell展开为T次调用，明确T是序列长度、t是序列位置而非墙上时间；
5. 最后解释参数共享、顺序依赖、BPTT、复杂度和硬件边界。

BPTT首屏必须同时给出三段清晰顺序：前向从早到晚、暂存反向所需中间结果、反向从损失走回较早位置。先说明“展开”只是把同一Cell的多次调用画开，权重仍只有一份；再讲共享权重的各步梯度贡献相加。不得先让读者点击时间步、解码激活磁带或读取无来源梯度数值。

### 链式法则与长路径梯度

先用最多两步、三个已定义量回答“早期输入改变一点，最终结果会改变多少”。首例不引入不必要的三角函数、多个中间字母或可选输入。前向值、相邻局部变化率、总变化率应分两行直接标注，并明确它为什么能把末端损失传回早期参数。迁移到RNN后再增加时间链长度。

### 激活内存与重计算

先跟踪一份具体中间张量的生命周期：前向产生 → 暂存 → 反向读取 → 释放。读者理解保存原因后，再比较训练与推理。激活检查点/重计算必须独立解释为“前向少存区域内部状态，反向前重跑该区域以重建状态”，不能只作为第三个按钮或一句策略名出现。

## 5. 反模式

- 以“点击三个实验观察……”开场。
- 用“不要只看最后一个 checkpoint”这类结论不完整的工程口号代替解释。
- 控件先出现，定义后补。
- 页面要求用户猜颜色、点、线和网络节点代表什么。
- 同一交互同时教授模型复杂度、早停、损失函数、决策边界和超参数选择。
- 已经显示答案后再问同义诊断题。
- 动画在动，但关键值、结构或结论没有变化。
- 用四步或更多数值动画作为结构概念的第一个入口。
- 一张图里出现大量字母和文字，却没有就近标出输入、处理、输出与方向。
- 默认页面只有操作说明，核心结论必须点击后才能拼出来。
- 先列“几个量分别是什么”，却尚未出现包含这些量的公式或结构。
- 因为所有词条都要“统一”而复用不适合概念的图形。
- 用总损失最低证明正则化最好。
- 公式直接显示源码标识符和裸下划线。
- 标题或首屏以“为什么不等于……”“不要误以为……”开场，而正文尚未正向讲清概念本体。
- 没有题目、用户反馈或审查证据支持，却主动加入防御性比较、反驳或假想误区。

## 6. 三次审查门

### 设计前：教学命题

- 核心结论能否用一句自然语言说清？
- 读者已掌握哪些前置概念？哪些可直接承接，哪些仍需补最低解释？是否重复了基础词条的教学？
- 当前是否有真实证据表明必须处理某个混淆？如果没有，不设计防御性区分。
- 交互是否必要？它只验证哪一条因果关系？

### 实现前：纸面走查

- 在不操作页面的情况下，独立读者能否复述概念与比较轴？
- 本页新引入的名词、符号、颜色、图形和控件是否就近介绍？是否把具体机制、抽象命名和边界挤在同一段？
- 图的结构是否就是概念发生的结构？
- 初始、变化、结果和解释能否一一对应？
- 不看操作说明，读者能否在30秒内沿图说出“输入 → 处理 → 输出”？
- 删除所有控件后，页面是否仍能解释概念本体？若不能，先补静态结构而不是继续设计控件。
- 是否在一个视区内同时要求读者解码过多新对象？若主线需要跨看多处图例或反复回读，拆分层次。

### 交付前：反向讲解

让未参与设计的审查者仅凭页面回答五个目标问题。再检查：

- 所有控件均可操作，包括第一个选项；
- 每个状态变化明显，文本与数值同步；
- 无装饰性或歧义模块；
- 公式上下标正确，符号解释完整；
- 键盘和触屏可用，颜色不是唯一编码；
- 术语链接能进入、继续深入并返回原路径；
- 示例数值与公式手算一致；
- 查看不同对象时数值保持不变；改变输入、经过关键分界点并恢复后，全部相关结果与解释一致；
- 没有把训练、验证、测试数据角色混淆。

## 7. 交付停止条件

下列任一项不满足，词条不得标记完成：

1. 具备约定前置知识的读者能从首屏辨认概念及其核心特点，并沿正文理解因果。
2. 交互有唯一教学问题，并产生可见、可解释的变化。
3. 新对象就近解释，已约定的前置知识可以承接。
4. 公式、示例和实现数值一致。
5. 适用场景和事实边界明确；若没有真实混淆证据，不要求也不主动生成“常见误区”。
6. 独立审查者无需设计者口头补充即可讲明白。
7. 独立审查者无需先学习交互模块本身；默认状态已经直接呈现核心对象、方向与结论。
