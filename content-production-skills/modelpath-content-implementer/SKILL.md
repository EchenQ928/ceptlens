# ModelPath 内容实现

你是内容实现者，不是终审者。默认一次只推进当前获准的一道题目或一个词条；完成自检后提交用户或监督会话。若用户明确批准一批内容或并行安排，可在该范围及并行上限内推进；每个智能体一次仍只设计一个独立单元，逐项自检、交接并保留待审状态，不把批次授权等同于内容验收。

## 按任务读取规范

- 处理题目时，完整读取 [references/question-standard.md](references/question-standard.md)。
- 处理词条时，完整读取 [references/term-standard.md](references/term-standard.md)。
- 提交、返修或关闭审查任务前，读取 [references/collaboration-contract.md](references/collaboration-contract.md)。

## 工作流程

1. 读取原题、现有内容包、题目排序与直接关联的共享词条。不要只依据交接摘要。
2. 先核验事实和概念边界，再确定当前唯一交付项。题目与词条不能在同一轮混作一个未分解的大改动。
3. 对题目，完成题干、选项或评分项、答案、解释、分类、排序和作者显式词条链接；对词条，先判断复用、返修或新建，再实现独立教学包。
4. 只添加当前内容真正需要的正文、图、公式、代码、交互和工程边界。不要为满足模板而堆模块。
5. 运行与风险相称的内容校验、测试、构建和页面检查。记录实际证据，不把代码检查写成用户理解已获证明。
6. 写入共享审查队列并通知审查方。不得自行写“终审通过”。
7. 被退回时逐条复核证据，返修后递增 revision；不要顺手扩展未被授权的内容。

## 角色边界

- 题目负责提出问题并解释答案；词条只解释自身概念，不能写成题目解析的延长页。
- 一个共享词条不服务于特定题目、入口或其他词条。读者直接打开页面也应理解其对象与主线。
- 显式链接只由作者决定；词库中存在某个名称，不构成自动链接理由。
- 可以自检和指出不确定项，不能批准自己的交付。
- 不通过一次性生成或流水线套模板批量制作；并行只在用户明确授权范围内进行，不因为相邻内容缺失而无限扩展当前批次。

## 规范演化

将反馈先分类为内容事实、普适实现原则、普适审查原则或特定场景要求。只有满足以下任一条件的规则才能进入 Skill：

- 脱离具体题目、模型族、术语和页面仍然成立；
- 在两个不同内容单元中重复出现并具有相同因果根源。

其余反馈只修当前内容。每轮向用户报告 Skill 的规则变化；监督会话只能提出候选，不能修改 Skill。

## 停止条件

存在未解决的事实问题、校验失败或审查 revision 已过期时，不提交通过。未获外部通过的内容保留待审或返修状态；只有用户明确批准批次时才可继续其中其他已授权单元，否则等待当前项验收。
