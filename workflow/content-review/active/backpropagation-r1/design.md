# 反向传播：实现前设计

读者理解预测、参数、激活和损失，但不假设学过链式法则。先建立“参数稍变，损失怎样变”的感性认识，再命名梯度。页面不依赖从哪一页进入。

学习顺序：前向得到预测与损失 → 用局部变化理解梯度 → 在同一张图上从后往前传梯度 → 链式法则 → 优化器更新 → PyTorch。

最小网络：x=2；第一层 z=w1*x+b1，w1=1、b1=-1，z=1；h=ReLU(z)=1；第二层 yhat=w2*h+b2，w2=2、b2=0，yhat=2；目标 y=3，平方损失 L=1。

完整前向路径与反向路径同时可见。箭头区分方向，数值在连接上，节点表示运算；权重、偏置旁标初值。选步骤只切换强调与演算，不改变已算出的前向数值或梯度。

反向四段：
- 损失对预测：2*(2-3)=-2。预测 +0.01 时损失从 1 到 0.9801，解释 -2 是当前附近的变化率，不是损失本身。
- 第二层：传到 h 的梯度 -2*2=-4；w2 梯度 -2*1=-2；b2 梯度 -2*1=-2。
- 激活：z=1 在 ReLU 正区间，局部变化率 1，故传到 z 的梯度 -4。
- 第一层：w1 梯度 -4*2=-8；b1 梯度 -4*1=-4。

核心计算：从后面来的梯度 × 当前步骤的局部变化率。先文字与算术后偏导符号。分支汇合需要相加，放在可展开补充；主图聚焦单链。ReLU 负区间为 0 的边界就近一句说明。

参数更新另节静态前后对照，避免与反向查看混淆：普通 SGD，学习率 0.025，参数同时更新为 [1.2,-0.9,2.05,0.05]；新预测 3.125，新损失 0.015625。明确 backward 计算梯度，step 才修改参数；梯度只是局部信息，步长并非越大越好。

验证：手算、中心差分与 PyTorch autograd 三方核对；各查看步骤前向值不变，强调节点/梯度/演算一致；代码输出与更新后前向一致；桌面视觉及最终 ZIP。
